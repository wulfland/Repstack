## Root cause

Commit `3419a4c` changed `vite.config.ts` to read `PUBLIC_BASE_URL`, while the deploy workflow still supplied `BASE_URL`. The build therefore used Vite's `/` default instead of `/Repstack/`, so the deployed page requested its JavaScript and CSS at the wrong root paths. The app never rendered: the health-check smoke test could not find either the onboarding screen or the main app, and the deploy's onboarding E2E tests could not find `h1.logo-text`.

The build and Pages deployment steps succeeded because the mismatch is only observable when the deployed app loads its assets. Deployment runs the E2E suite after publishing, so the broken artifact was already live when that check failed. The health-check probe uses `continue-on-error` so it can open an incident; its overall workflow conclusion is consequently `success` even when the probe fails.

## Blast radius

Visitors to the GitHub Pages app could not load the UI while the bad base path was deployed. Existing training data in IndexedDB was unaffected.

## Remediation

Production remains unhealthy. Redeploying the last green commit `edd57fb724b7b7bc0473a9487a23b6ab54aecf5a` was attempted through the allowed workflow dispatch, but the dispatch was denied and no GitHub CLI token was available. A green health check is still required before closing the incident.

## Permanent fix

Pass `PUBLIC_BASE_URL` to the deploy build so its configured base path matches the Vite configuration.
