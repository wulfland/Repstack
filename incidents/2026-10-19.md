## Root cause

The deployment workflow passed `BASE_URL`, but `vite.config.ts` reads `PUBLIC_BASE_URL`. The build therefore used Vite's `/` default instead of `/Repstack/`, so the deployed page referenced assets outside the GitHub Pages project path and the application did not load. The HTTP probe still passed because GitHub Pages served the HTML. The deployment workflow's end-to-end tests run only after deployment, so a successful build could publish the broken page before those tests caught it.

## Blast radius

Visitors to the production site could load the HTML but not the app while the broken deployment was live. Locally stored user data was unaffected.

## Remediation

The health-check pipeline started an automatic redeploy of the last green commit, `f182c4fa842fe4def071e47978ce2dd42589375e`. The deploy run is still in progress; a human must step in if it fails or a later health check remains red.

## Permanent fix

Pass `PUBLIC_BASE_URL` to the Vite build so its configured base path matches the GitHub Pages project URL. This keeps asset, manifest, and PWA paths under `/Repstack/`.
