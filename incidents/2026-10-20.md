## Root cause

Commit `27feb699` changed `vite.config.ts` to read `PUBLIC_BASE_URL`, but `.github/workflows/deploy.yml` supplies `BASE_URL`. Vite therefore built with the default `/` instead of `/Repstack/`. The GitHub Pages HTML remained reachable, so the HTTP probe and build succeeded, but the app's JavaScript assets were requested from the wrong paths and the browser smoke test could not see the app. The deployment E2E check runs after publishing, so it detected the problem only after production had changed.

## Blast radius

Visitors could reach the production page but not load the app while the broken build was deployed. Local IndexedDB data was unaffected. The rollback's production E2E check and the subsequent scheduled health check passed.

## Remediation

The health-check pipeline automatically dispatched the rollback to the last green commit. No manual redeploy or workflow dispatch was performed.

## Permanent fix

This PR restores Vite's `BASE_URL` lookup to match the deploy workflow, so GitHub Pages builds use the repository subpath.
